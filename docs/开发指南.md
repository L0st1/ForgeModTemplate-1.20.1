# Forge Mod 模板开发指南

## 技术基线与元数据

项目基线为 Minecraft 1.20.1、Forge 47.4.0、Java 17 和 Gradle 8.8。`gradle.properties` 是 Mod ID、名称、版本、作者、许可证、描述和技术版本的规范来源；`build.gradle` 在 `processResources` 阶段生成 `mods.toml` 与 `pack.mcmeta` 中的最终值。

修改版本时只需要更新 `mod_version`，随后检查 JAR 文件名及内部 `META-INF/mods.toml` 是否同步变化。

## 公共端与客户端边界

公共 Mod 入口必须能在专用服务器加载，不得直接导入 `net.minecraft.client.*`、GLFW 或渲染类。按键、HUD、渲染和仅本地提示放在 `client` 包，并通过 `Dist.CLIENT` 限定事件订阅。

玩家生命值、背包、方块、实体和世界状态由服务端决定。客户端按键若要改变这些状态，应发送限定为 `PLAY_TO_SERVER` 的消息；服务端处理器验证 `context.getSender()` 和输入范围，再通过 `enqueueWork` 修改状态。

## 可选模块

### Mixin

优先使用 Forge 事件、注册器、配置和公开 API。只有目标行为硬编码且没有稳定扩展点时才使用 Mixin。启用后同步检查 `enable_mixin`、annotation processor、Mixin JSON、refmap 和 JAR manifest。

### Forge 配置

配置模块提供 common 配置示例，由公共入口注册。新增配置项时给出边界、默认值和中文注释，不在静态初始化期间读取依赖游戏世界的状态。

### 网络通信

每种消息固定协议版本、唯一 ID 和方向。C2S 处理必须允许 sender 为空的异常路径安全退出，并避免在网络线程直接修改世界。

### GameTest

适合验证注册结果、方块或实体行为等无需完整图形客户端的逻辑。客户端 UI 和渲染仍需 `runClient` 冒烟检查。

## 开发运行

生成 IDEA/Eclipse 运行配置或直接运行：

```powershell
.\gradlew.bat genIntellijRuns
.\gradlew.bat runClient
.\gradlew.bat runServer --args="--nogui"
.\gradlew.bat runGameTestServer
```

服务器首次启动可能要求处理测试目录中的 EULA；不要把个人 `run/` 内容提交到模板。

## 构建产物

统一入口 `scripts/build-local.ps1` 会先运行环境诊断，检测已存在的 Spotless、Checkstyle 或 lint 任务，执行测试并构建 JAR。任何步骤失败都会返回非零退出码。

构建后至少检查：

- JAR 名称符合 `<mod_id>-<mod_version>.jar`；
- `META-INF/mods.toml` 不包含 `${...}`；
- 资源位于 `assets/<mod_id>/`；
- 启用 Mixin 时 manifest 包含 `MixinConfigs`；
- 公共入口字节码不引用客户端包。

## 常见故障

### Java 版本错误

运行 `scripts/doctor.ps1`。模板要求 Java 17；高版本 JDK 不作为模板默认验证目标。配置 `JAVA_HOME` 后重新打开终端。

### 代理不可达

默认代理是 `127.0.0.1:7890`。启动本机代理，或创建 `config/network.local.properties` 并设置 `proxy.enabled=false`。不要删除受版本控制的默认配置。

### 插件或依赖解析失败

先区分代理、仓库连接和缓存问题，再处理 Gradle 配置。可以在确认网络正常后使用 `gradlew --refresh-dependencies`；不要把依赖下载失败当成 Java 编译错误。

### 专用服务器出现客户端类错误

检查公共入口、公共事件处理器和静态字段是否导入 `net.minecraft.client`。把相关代码移动到 `client` 包并增加 `Dist.CLIENT` 限定；若功能改变权威状态，补充网络消息和服务端处理。

### Mixin 找不到目标

确认依赖 Mod 与开发时版本一致，使用 `javap` 或反编译工具核对实际类名、方法描述符和映射；避免凭记忆修改注入点。
