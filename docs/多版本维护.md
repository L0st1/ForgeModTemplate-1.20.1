# 多版本维护指南

## 版本策略

仓库使用一个 Minecraft 版本一个分支的策略：

```text
main        当前默认基线，Minecraft 1.20.1
mc-1.20.1   Minecraft 1.20.1 的稳定分支
mc-1.21.1   Minecraft 1.21.1 的适配分支
```

不同版本分别使用对应的 Forge、映射和 Java。不要让一个分支同时承载两个不兼容的 Forge 主版本。

## 创建版本分支

在提交完当前修改后运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\create-version-branch.ps1 `
  -Version 1.21.1 `
  -ForgeVersion 52.0.0 `
  -ForgeLoaderRange '[52,)' `
  -MinecraftRange '[1.21.1,1.22)' `
  -JavaVersion 21
```

参数中的 Forge 版本和 Java 版本只是示例，必须替换为目标版本 Forge MDK 的实际值。脚本只负责创建分支和更新版本元数据，不会自动修复 Forge API 变化。

## 适配检查清单

- 更新 `gradle-wrapper.properties` 和 Forge Gradle 插件版本；
- 检查 Java toolchain 与目标 Minecraft/Forge 要求一致；
- 检查 `src/main/java` 中被移除或改名的 Forge API；
- 检查 `mods.toml`、`pack.mcmeta` 和数据生成格式；
- 运行 `scripts/doctor.ps1` 与 `gradlew.bat build`；
- 在目标 Minecraft 客户端和专用服务器分别验证；
- 推送分支并创建对应 GitHub Release。

## 发布约定

JAR 文件应明确包含 Minecraft 版本，例如：

```text
my_mod-0.1.0-mc1.20.1.jar
my_mod-0.1.0-mc1.21.1.jar
```

GitHub Template 只用于创建新 Mod 项目；使用者应先点击 `Use this template` 创建独立仓库，再运行初始化脚本。
